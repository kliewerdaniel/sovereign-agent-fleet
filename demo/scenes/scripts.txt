T01|Welcome to the Sovereign Agent Fleet. This is a Fortified Enterprise agent system, built for one hard problem: an AI fleet that can act on real business outcomes, but only under cryptographic authority and human approved consequential actions. Everything you see in this demo is produced by the actual system, not by slides.
T02|Let's start with the threat model we designed against. First, a prompt injection tries to make the agent exfiltrate data or misdirect it. Second, a capability escalation, where a worker attempts an action it was never granted. Third, a forged identity that tries to impersonate a trusted agent. And fourth, a tampered cloud log that edits history after the fact to hide what actually happened.
T03|Here is the architecture. A deterministic control plane wraps a pluggable model brain. The model only proposes. The control plane decides. Three workers form the pipeline. A Researcher gathers evidence. An Analyst qualifies that evidence into verified intelligence. And an Operator acts on it. Evidence becomes qualified intel becomes a final, recorded action.
T04|We prove the security with real tests, not slides. This is our adversarial beat suite: nine end to end scenarios. Prompt injection is blocked structurally. Capability denial emits a signed gateway event. A consequential action without human approval is refused. Every single beat passes.
T05|Now the most important beat. A legitimate action still needs a human signature. The human signs an approval record that is cryptographically bound to the exact action id, the capability, and the artifact hash. The operator only reaches a final committed state once that valid approval is present. Authority stays with the human.
T06|Every action is signed, chained, and replicated. Here the operator's final action and all of the preceding events are mirrored to the cloud store as signed documents. The local chain verifies true, and eleven signed documents are replicated to live Firestore.
T07|And the cloud copy is verifiable with public keys only. The verifier holds data, not authority. When an adversary edits even one replicated document after the fact, public key verification catches the break immediately. Tamper detected. Notice no private key is ever used by the verifier.
T08|This is the LIVE deployment. Not a local mirror. The fleet runs on Google Cloud Run, in region us-central1. A real Firestore database holds the signed ledger, a real Pub/Sub topic carries handoffs, and a live approval console serves the human sign-off. The Cloud Run instance never holds the root key or signs artifacts. It only verifies human signatures. Fail closed.
T09|Watch the live console. A consequential action is queued. The console accepts it only after verifying the human's Ed25519 signature is bound to the exact action. A mis-bound approval is rejected outright. The console requires the signature; it cannot forge one.
T10|The model brain itself is sandboxed by contract. It proposes classifications, but the control plane enforces the output schema before any record is written. Malformed or out of range proposals are rejected at the boundary. The brain never sees policy or approval vocabulary. The model proposes, the plane decides.
T11|This is the honest version. The GCP proof you just saw is LIVE: a real Firestore database, a real Pub/Sub topic, a real Cloud Run console, all on public key verification. There is no private key in the verifier. Local first, verifiable, and sovereign.
